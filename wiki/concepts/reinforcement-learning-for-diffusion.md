# Reinforcement Learning for Diffusion（拡散モデルの強化学習・事後学習）

**Reinforcement Learning for Diffusion（拡散モデルの強化学習）** とは、事前学習を終えた画像生成モデルを、**人間の好みや報酬モデルの評価に合わせて仕上げる**技術の総称である。大規模言語モデル（LLM）で ChatGPT を生んだ RLHF（Reinforcement Learning from Human Feedback, 人間のフィードバックによる強化学習）と同じ発想を、拡散モデル／[[flow-matching]] モデルに持ち込むもので、**事前学習 → SFT → RL** という 3 段構えの最後の工程にあたる。本 wiki のランドマークは **Qwen-Image**（[[summaries/2025-qwen-image]]）で、DPO と Flow-GRPO を組み合わせて GenEval を 0.87 → **0.91** に押し上げた。

## なぜ事後学習が必要なのか

事前学習の目的関数（ノイズ／速度の二乗誤差回帰）は、**「学習データの分布を再現せよ」**としか言っていない。しかし実際にユーザーが欲しいのは、

- プロンプトへの忠実さ（指示した物体・数・位置がちゃんと出る）
- 美的品質（構図・照明・"AI っぽさ"のなさ）
- 破綻のなさ（指が 6 本にならない）

といった、**データ分布そのものには書かれていない「良さ」**である。学習データには凡庸な画像も破綻した画像も混ざっているのだから、分布を忠実に再現するだけでは足りない。そこで、**人間の選好や報酬モデルという別の信号**でモデルを微調整する。

なお、推論時に条件への忠実度を上げる [[classifier-free-guidance]] も似た効果を狙うが、あれは**サンプリング時のノブ**であり多様性とのトレードオフが避けられない。強化学習は**モデルの重み自体**を good な方向へ動かす点で相補的である。

## 拡散モデル特有の難しさ

LLM の RL をそのまま持ち込めない理由がいくつかある。

- **生成が多ステップの軌道である**：1 枚の画像は数十ステップのノイズ除去の連鎖の果てにできる。報酬は最後の画像にしか付かないのに、**どのステップの判断が良かったのか**を割り当てる必要がある（信用割り当て問題）。
- **尤度が扱いにくい**：LLM ならトークンごとの確率が直接得られるが、拡散モデルの尤度は明示的でない。方策比の計算に工夫が要る。
- **flow matching は決定論的**：[[flow-matching]] の ODE サンプリング（[[probability-flow-ode]]）は、初期ノイズを決めれば軌道が一意に決まる。**ランダム性がないと探索できない**ので、オンポリシー RL がそのままでは成立しない。

## 2 つの系統：DPO と GRPO

Qwen-Image は 2 手法を役割分担させる——**DPO で大規模に、GRPO で小規模かつ細粒度に**。

### (A) DPO（Direct Preference Optimization, 直接選好最適化）

**報酬モデルを別途学習せず、「良い例／悪い例」の対比較データから直接最適化する**手法。LLM 向けに提案され、拡散モデルへ移植された（Diffusion-DPO）。

- **データ**：同じプロンプトから異なるシードで複数枚生成し、人間のアノテータが **best と worst** を選ぶ。参照（golden）画像がある場合は、参照と大きく食い違う生成を拒否サンプルに指定する。
- **アルゴリズム（Qwen-Image の定式化）**：flow matching の学習基準の上に DPO を構成する。すなわち、勝ち画像 $x_0^{win}$ と負け画像 $x_0^{lose}$ それぞれについて**速度予測誤差**を計算し、その差（$\text{Diff}_{\text{policy}}$）を参照モデルの同じ差（$\text{Diff}_{\text{ref}}$）と比べて、シグモイド対数尤度を最大化する。直感的には「**勝ち画像は今より上手く、負け画像は今より下手に予測するよう重みを動かす**」。
- **利点**：1 ステップで済み計算効率が良く、オフラインの選好データを使えるのでスケールしやすい。だから Qwen-Image は**大規模 RL を DPO で回す**。

### (B) GRPO（Group Relative Policy Optimization, グループ相対方策最適化）

**同じプロンプトから生成した「グループ」の中で報酬を相対比較する**オンポリシー手法。価値関数（critic）を持たずに済むのが特徴で、LLM の推論強化で有名になった。

- **アドバンテージ**：グループ内 $G$ 枚の報酬を平均・標準偏差で標準化する（$A_i=(R_i-\text{mean})/\text{std}$）。「このグループの中で相対的に良かったか」だけを見るので、報酬のスケールに鈍感になる。
- **目的関数**：方策比 $r_t^i(\theta)$ にクリップをかけた PPO 型の目的に、参照方策からの KL 罰則を加える。
- **flow matching への適用（Flow-GRPO）**：ここが技術的な要点。決定論的な ODE サンプリングでは探索ができないため、**サンプリング過程を SDE に再定式化してランダム性 $\sigma_t$ を注入する**。Euler-Maruyama 離散化で軌道をサンプルし、KL ダイバージェンスは閉形式で計算できる。ODE と SDE が同じ確率パスの異なる実現であるという [[stochastic-interpolants]] 的な性質を、**探索性を得るために使う**わけである。
- **コスト**：学習中に毎回サンプリングするため重い。よって Qwen-Image は**小規模な仕上げ**に限定する。

## 報酬設計の精緻化：タスクごとに報酬を分ける（2026）

初代 Qwen-Image が「DPO で大規模に、GRPO で細かく」という**アルゴリズムの使い分け**を示したのに対し、後継の **Qwen-Image-2.0**（[[summaries/2026-qwen-image-2]]）は**報酬側を細分化**した。単一の「良さ」で測るのをやめ、**5 つのタスク特化型報酬モデル**を別々の人手選好データから構築する。

| 報酬 | 対象 | 何を測るか |
| --- | --- | --- |
| 美的報酬 | T2I | 構成のバランス、写実的な照明、テクスチャ、芸術的一貫性 |
| 画像テキスト整合報酬 | T2I | プロンプトの要求を省略・誤解・矛盾していないか |
| 肖像報酬 | T2I | 解剖学的妥当性、顔の比率、同一性、肌と髪の質感 |
| 指示追従報酬 | TI2I | 指示された修正（置換・スタイル転送等）が実行されたか |
| 視覚的一貫性報酬 | TI2I | 未修正領域の幾何・空間位相・意味が保たれているか |

すべて比較可能なスケールに較正され、**重みは学習中に動的に調整**される——単一次元への過剰最適化（＝報酬ハッキング）を避けるためである。[[instruction-based-image-editing]] の「2 つの一貫性」がそのまま TI2I の 2 報酬に対応している点が示唆的で、**タスクの要件分解がそのまま報酬設計になる**という設計思想が読み取れる。

もう 1 つの実務的な工夫が **CFG のハイブリッド戦略**である。拡散 RL では「ロールアウトと方策最適化で [[classifier-free-guidance]] を使うべきか」で先行研究が割れていた（両方で使う／完全に使わない）。Qwen-Image-2.0 は中間を採る——**ロールアウトのサンプリングでは CFG を使って高品質な候補を作り報酬評価を信頼できるものにしつつ、無条件分岐は方策最適化の目的から除外する**。これにより報酬信号の質を保ちながら、無条件モデルを最適化する計算を省ける。

## 報酬を「推論そのもの」にも向ける（2026）

**HiDream-O1-Image**（[[summaries/2026-hidream-o1-image]]）の RLHF は GRPO を使い、報酬を **OCR 正確性・美的評価・指示追従忠実度・推論品質**の 4 系統集約する。前 3 つは Qwen-Image-2.0 の 5 報酬と重なるが、4 つ目の「**推論品質（reasoning quality）**」が新しい。

このモデルはユーザーの生の指示をそのまま使わず、**Reasoning-Driven Prompt Agent**（Gemma ベース）が空間配置・被写体の属性・物理的な論理・文脈的関係について思考の連鎖（chain of thought）を明示的に生成してから、最終的なプロンプトを書き出す。RL の最適化対象には**このエージェント自身**も含まれる。Qwen-Image-2.0 の Prompt Enhancer が「書き換え結果を下流の画像品質で評価される」だけだったのに対し、こちらは**中間の推論過程の質そのものを報酬化する**。

前処理（プロンプト）・生成本体・事後学習が別々の部品ではなく、**1 つの最適化ループに入る**という方向であり、本ページ冒頭の「事前学習の定式化競争から、パイプライン全体の設計へ」という流れをさらに一歩進めたものと位置づけられる。

## 正則化子をどこから調達するか（2025）

RL を生成モデルに掛けるときの最大の実務的リスクは **報酬ハッキング（reward hacking）** ——モデルが報酬関数を悪用し、スコアは高いが視覚的に意味をなさない画像を作る現象——である。通常はこれを防ぐために外から正則化（元モデルからの KL 制約など）を足す。

**Z-Image**（[[summaries/2025-z-image]]）の **DMDR** は、この正則化子を**蒸留の側から調達する**。著者らは Decoupled DMD の分析で「DMD の Distribution Matching 項は実は正則化子として働いている」ことを突き止めており（[[diffusion-distillation]]）、ならばそれをそのまま RL の制約に流用できる、という筋である。RL が人間の選好への整合を解き放ち、DM 項が報酬ハッキングを押さえる。**事後学習と蒸留が別工程ではなく同じ損失の中で役割分担する**という点で、本ページの構図を一段組み替える発展になっている。

### DPO と GRPO の分担を「検証可能性」で切る

Z-Image はもう 1 つ、実務的に再利用価値の高い切り分けを提示する。本ページで DPO（オフライン・選好ペア）と GRPO（オンライン・報酬モデル）を 2 系統として並べたが、**どちらをどの次元に使うか**の基準を明示する。

- **DPO は客観的で二値判定できる次元だけ**に限定する——テキストレンダリングの正誤、物体の個数。これらは **VLM が自動で正解・不正解を判定できる**ので、選好ペアをプログラム的に大量生成し、人間は検証だけすればよい。アノテーションのスループットが劇的に上がる。
- **主観的な次元**（美しさ、様式）は、一貫して情報量のある選好ペアを集めるのが遅く専門家を要するため DPO では扱わず、**GRPO のオンライン精錬**に回す。

「選好ペアを作るコスト」が次元によって桁違いに違う、という観察に基づく分担である。DPO 側にはさらにカリキュラム学習を入れ、**差異が中程度のペアから始めて徐々に大きい／微妙な差異へ**進む（DPO の収束が正例と負例の差の度合いに敏感だという観測に基づく）。

なお報酬モデルのアノテーション設計も具体的である。指示追従については、プロンプトを (i) 中核となる主体、(ii) 属性、(iii) 動作・相互作用、(iv) 空間・構図の制約、(v) 様式・レンダリングの条件へ構文的・意味的に分解し、**人間の評価者は満たされていない要素をクリックするだけ**にする。満たされた要素の比率がそのままスコアになる——採点者の負担を下げつつ細粒度の信号を得る工夫である。

## 効果と限界

**効果**（Qwen-Image, GenEval）：SFT 版 0.87 → RL 版 **0.91**。とくに **Position 0.76→0.87**、**Attribute Binding 0.77→0.83**、Counting 0.89→0.93 と、**「指示どおりに配置・属性を割り当てる」という構成的な正確さ**が大きく伸びた。リーダーボードで唯一 0.9 を超える基盤モデルになった。

**限界・注意点**：

- **報酬ハッキング**：報酬モデルの穴を突いて、スコアは高いが人間には不自然な画像へ寄る危険がつきまとう。KL 罰則や参照モデルはこれを抑えるための安全装置である。
- **選好データのコスト**：DPO は人手アノテーションが前提で、収集の質がそのまま上限になる。
- **多様性の低下**：好まれる出力に寄せるほど生成の多様性が落ちうる（CFG と同種のトレードオフ）。
- **評価の妥当性**：改善が特定ベンチマーク（GenEval など）に最適化されただけでないかは別途検証が要る。Qwen-Image でも ablation は GenEval での SFT 対 RL 比較にとどまる。

## 既存知識との接続

- [[flow-matching]]：Qwen-Image の DPO は**速度予測誤差**の差で選好を定義し、GRPO は flow のサンプリングを SDE 化して探索性を得る。どちらも flow matching の定式化の上に直接構築される。
- [[probability-flow-ode]] / [[stochastic-interpolants]]：「決定論的 ODE と確率的 SDE は同じ確率パスの異なる実現」という性質が、Flow-GRPO の SDE 再定式化の理論的な足場になる。
- [[classifier-free-guidance]]：推論時に条件忠実度を上げるノブ。RL は重み自体を動かす事後学習で、両者は併用される（Qwen-Image も CFG を使って生成する）。
- [[text-to-image-generation]]：事後学習は T2I 基盤モデルの品質を最後に詰める標準工程になりつつある。
- [[diffusion-sampling]]：GRPO のサンプリング（Euler-Maruyama）はサンプラー設計と直結する。

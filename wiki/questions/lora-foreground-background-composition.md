# 前景物体 LoRA × 背景スタイル LoRA をどう合成するか

> 質問: 拡散モデルで前景（iPhone などの特定の物体）と背景のスタイルをそれぞれ LoRA で学習し、最終的に前景と背景をいい感じに合成したい。おすすめの手法は？
> 回答日: 2026-08-19

## 結論（試す順序）

1. **K-LoRA**（[[summaries/2025-k-lora]]）で単一パスを試す — 被写体の同一性で最も強い
2. 物体の同一性が足りなければ **NP-LoRA**（[[summaries/2025-np-lora]]）へ切り替え、$\mu$ を 0.5 → 0.2 と下げる
3. 配置を制御したくなったら **LoRA-Composer**（[[summaries/2024-lora-composer]]）— 前景／背景分離損失を持つ
4. それでも物体の見た目が許容できなければ **背景生成 → AnyDoor / inpainting の逐次パイプライン**（[[summaries/2023-anydoor]]）

## 最初に切り分けるべき 2 点

### (1)「背景のスタイル」の正体

| | 背景の正体 | 該当する問題設定 |
| --- | --- | --- |
| **(A)** | 画像全体にかかる**様式**（水彩画風・サイバーパンク風など） | [[style-content-disentanglement]] の content × style |
| **(B)** | **特定のシーン**（あの部屋、あの机の上） | [[multi-concept-customization]] の第 2 の概念 |

(A) なら LoRA 融合系（K-LoRA / NP-LoRA）、(B) なら空間制御系（LoRA-Composer / Mix-of-Show）が本来の想定に近い。

### (2) 融合手法は「配置」を解かない

**これが最も重要な前提である。**

> LoRA 融合の手法群が解いているのは「**互いを壊さないこと**」であって、「**前景をどこに置くか**」ではない。

推測ではなく [[summaries/2024-orthogonal-adaptation]] が限界として明記している。同論文は「マージしても各概念が壊れない」ことを解いた一方、**複数概念を 1 枚に破綻なく構図することは未解決**とし、先行研究の空間ガイダンス（Mix-of-Show の regionally controllable sampling）を借用してなお「概念が無視される」「属性が隣接概念へ漏出する」失敗が残ると報告している。

「iPhone を画面の右下に、この画風の背景の上に」をやりたいなら、融合手法**だけ**では届かない。

## 推奨 A：単一パスで融合する（背景 = 様式）

### K-LoRA と NP-LoRA は評価軸の鏡像

| | 被写体（物体の同一性） | スタイル（背景の画風） |
| --- | --- | --- |
| **K-LoRA** | **CLIP 69.4 / DINO 46.9（1 位）** | 58.7（3 位） |
| **NP-LoRA** | 0.73（K-LoRA 0.76 に劣る） | **CLIP 0.59 / DINO 0.33（1 位）** |

両論文の事実認識は一致している——NP-LoRA は本文で「K-LoRA は被写体の同一性をよく保存するが、所望のスタイルの捕捉に苦戦する」と明記する。

**iPhone のような「形・比率・ロゴが正確でないと即バレる剛体」が対象なら、被写体側で勝つ K-LoRA から試すのが理にかなう。**

### NP-LoRA の $\mu$ は意味の明快なつまみ

$$P_{\text{soft}}=I-\tfrac{\mu}{1+\mu}V_{k}V_{k}^{\top}$$

- $\mu \to 0$：直和に近づく＝**コンテンツ優勢**
- $\mu = 0.5$（既定）：均衡
- $\mu \to \infty$：硬射影＝**スタイル優勢、コンテンツが削られる**

物体の同一性が崩れたら $\mu$ を下げればよい。K-LoRA の $\alpha,\beta$ より調整の意味が明快である。

**ただし NP-LoRA の射影は非対称**で、守られるのは常にスタイル側。逆向き（スタイルをコンテンツの零空間へ）は原典で試されており、**スタイルの痕跡がほぼ完全に消える**ため使えない。「物体を守る」向きの選択肢は存在しない。

### 実務上のコスト

| | マージ時間 | 画像あたり生成時間 |
| --- | --- | --- |
| 直接マージ | 13.5 秒 | 22.9 秒 |
| **NP-LoRA** | 13.4 秒 | 23.2 秒 |
| **K-LoRA** | 12.3 秒 | **60.4 秒** |
| ZipLoRA | 10 分超 | 29.9 秒 |

K-LoRA は生成のたびに層ごとの選択が走るため **2.6 倍遅い**。この数値は K-LoRA 自身は報告しておらず、NP-LoRA の実測による。大量生成では効いてくる。

## 推奨 B：配置を制御する（背景 = 特定シーン、または前景の位置を決めたい）

**LoRA-Composer**（[[summaries/2024-lora-composer]]）が用途にほぼ名指しで対応する。学習不要、入力は**レイアウト（ボックス）＋テキスト**のみ。

- **Region-Aware LoRA Injection**：cross-attention で**領域ごとに別の LoRA を注入**。物体のボックスには物体 LoRA、それ以外には背景 LoRA
- **Region Perceptual Restriction**：**前景・背景間の相互作用を最小化する損失**。「背景の画風が物体を溶かす」のを直接防ぐ機構
- **Latent Re-initialization**：単一概念 LoRA は画像全体で学習されるため局所領域の生成に不向き。潜在を作り直して局所生成向けの空間 prior にする

融合の再訓練も、スケッチ／ポーズ等の画像条件も不要。

## 推奨 C：融合をやめて逐次にする

1. **背景 LoRA だけ**で背景画像を生成
2. **物体を後から置く** — [[image-composition]] の **AnyDoor**（[[summaries/2023-anydoor]]）なら参照物体をシーンの指定位置に zero-shot で合成できる。DINO-V2 の ID 特徴と高周波マップで同一性を保ち、照明・影・視点まで馴染ませる

**干渉問題を完全に回避する。** NP-LoRA の命題 1 が示すとおり加重マージでの干渉は原理的に消せないので、**そもそも混ぜない**のは正当な設計判断である。製品写真のように「物体の見た目が絶対」な用途では実務的に最も安定する。

## 工業製品を前景にするときの注意点

**1. 色がスタイル側に取られる。** [[summaries/2024-b-lora]] が限界として挙げるのがまさにこれで、**物体固有の色までスタイル成分に取り込まれ同一性が壊れる**。同論文の分析では SDXL の第 5 ブロックが支配するのは厳密には「スタイル」ではなく「**色**」だった。特定の色味が同一性の一部なら直撃する。対処としてスタイル側に係数 $\alpha \in [0.4, 0.5]$ を掛ける手当てが提案されている。

**2. ロゴと画面内の文字。** [[visual-text-rendering]] の領域。スタイル LoRA を強く効かせるとロゴや UI 文字は真っ先に崩れる。LoRA 融合ではどうにもならないので、必要なら後段の inpainting で入れ直す前提で設計する。

**3. 剛体は歪みが目立つ。** 犬や猫なら多少形が変わっても許容されるが、直線と角丸で構成された工業製品は数ピクセルの歪みが不自然に見える。被写体側の忠実度を優先する根拠がここにもある。

## 避けたほうがよいもの

| 手法 | 理由 |
| --- | --- |
| **素朴な線形和** | [[summaries/2025-np-lora]] の**命題 1**：加重和がスタイル成分を保つには $P\Delta W_c$ と $\Delta W_s$ が共線でなければならず、独立学習の LoRA ではほぼ確実にそうならない。**係数調整では解決しない** |
| **TIES / DARE** | 疎化系は忠実度を守る代わりに**タスクそのものを落とす**。[[summaries/2026-ssr-merge]] の実測で複数被写体の同時生成の成功率が素朴な和より低い（0.69・0.62 対 0.76）＝ concept vanishing |
| **ZipLoRA** | 動作はするが **content × style の組合せごとに再最適化**が要る。背景を差し替えるたびに学習が走る（[[summaries/2024-ziplora]]） |
| **共同学習（両方まとめて 1 つの LoRA）** | NP-LoRA の比較では**不安定**（$S_\text{harm}$ 0.43）。多目的最適化での破滅的忘却が原因と分析される |

## 評価するときの落とし穴

**被写体類似度とスタイル類似度を別々に見て順位を付けてはならない。**

K-LoRA の表にある共同学習が決定的な例で、**Style Sim 68.2%（全手法中最高）なのに DINO は 17.4%**。これは**スタイルを塗りつぶして物体を失った状態**だが、スタイル指標だけ見れば最良に見える。

NP-LoRA が導入した**調和平均 $S_\text{harm}$**（片方が低いと大きく下がる）を使うか、少なくとも 2 指標を必ず並べて見る。詳細は [[style-content-disentanglement]] の「評価の落とし穴」に整理してある。

## この回答の限界

**K-LoRA と NP-LoRA が評価されているのは「DreamBooth の被写体 × StyleDrop の画風」であって、「工業製品 × 背景シーン」ではない。** 前景／背景という空間的に分かれた構成は、これらの手法の想定外である。問題設定への当てはまりは推奨 B・C の方が良い、というのが率直な見立てになる。

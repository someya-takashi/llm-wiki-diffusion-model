# Wan: オープンで先進的な大規模動画生成モデル

> 原典: [[translations/2025-wan]] ・ `raw/papers/Wan_ Open and Advanced Large-Scale Video Generative Models.md`
> 著者・年: Wan Team（Alibaba Group）・2025 年 3 月・arXiv:2503.20314

## 一言まとめ

**動画生成の基盤モデルを、VAE・DiT・学習インフラ・推論最適化・評価ベンチマーク・7 種の下流応用まで丸ごと公開したテクニカルレポート**。14B と 1.3B の 2 サイズを Apache ライセンスで公開し、VBench で Sora を上回りつつ、1.3B は **8.19 GB VRAM** で動く。

## 背景と問題意識

本 wiki がここまで追ってきたのは一貫して**画像**の生成だった。動画に踏み出すと、**時間軸が 1 本増えるだけで問題の質が変わる**。Wan はその変化を全編にわたって具体的に記述しており、動画拡散（[[video-diffusion]]）の入口として本 wiki に最適な原典である。

何が変わるのか。最も直接的なのは**系列長の爆発**である。1280×720 の動画 81 フレームを DiT に流すと、潜在トークンは数十万から 100 万に達する。注意計算は系列長の**二乗**で効くので、著者らの実測では**系列長 100 万で注意が学習時間の 95% を占め**、14B モデルの活性化メモリは **8 TB** を超える。画像生成では「モデルを大きくする」が主な難所だったが、動画では「**1 サンプルが単一 GPU に載らない**」が先に来る。

もう 1 つは**時間的因果性**という新しい制約である。動画の VAE は、未来のフレームが過去のフレームの符号化に影響してはならない。これは画像の VAE には存在しなかった要求で、正規化層の選択にまで波及する（後述）。

論文の動機自体は素直で、オープンソースの動画モデル（HunyuanVideo・Mochi・CogVideoX）と商用モデル（Sora・Kling・Veo 2）の間に「性能・機能の幅・効率」の 3 つの隔たりがある、というものである。Wan の答えは、**その 3 つを 1 本のレポートで同時に埋める**という物量作戦になっている。

## 提案手法 / 主張

### 1. Wan-VAE — 時間軸を持つトークナイザ

<figure>

![](../../raw/assets/2025-wan/vae.png)

<figcaption>図5（引用）: Wan-VAE の枠組み。エンコーダは 3 段のダウンサンプリングを持ち、最初の 1 段は空間のみ 2 倍（緑）、残り 2 段が時空間とも 2 倍（橙）。結果として空間 8 倍・時間 4 倍の圧縮となる。</figcaption>
</figure>

[[image-tokenizer]] で整理した「圧縮率 $f$・チャネル数 $C$・再構成忠実度」の議論が、そのまま**時間方向へ拡張**される。Wan-VAE は $(1+T)\times H\times W$ の動画を $[1+T/4, H/8, W/8]$ へ圧縮し、チャネルは 16。**最初のフレームだけは空間的にのみ圧縮する**（MagViT-v2 由来）——これにより単一画像を「1 フレームの動画」として同じ VAE で扱えるようになり、画像と動画の共同学習が成立する。

固有の工夫が 2 つある。

**(a) GroupNorm を全部 RMSNorm に置き換える。** GroupNorm はフレーム群にまたがって統計量（平均・分散）を取るので、**未来のフレームの情報が過去へ漏れる**。RMSNorm は各要素の二乗平均だけで正規化するため、この漏れが起きない。**正規化層の選択が時間的因果性を壊すかどうかを決める**という、画像では意識しなくてよかった論点である。

**(b) 特徴キャッシュ機構。** 動画を $1+T/4$ 個のチャンクに割り、1 チャンク（最大 4 フレーム）ずつ符号化・復号する。チャンク境界で切れ目が出ないよう、**因果畳み込みの過去 2 フレーム分の特徴をキャッシュして次のチャンクへ引き継ぐ**（カーネルサイズ 3 なので 2 フレーム）。最初のチャンクだけはゼロ埋めのダミーで初期化する。これにより**任意長の動画を一定メモリで処理できる**——後述の Streamer による無限長生成の前提条件になっている。

結果、127M という極小サイズで PSNR と速度の両方で競争力を持ち、**HunyuanVideo の VAE より再構成が 2.5 倍速い**。

### 2. Video DiT — MM-DiT を採らない選択

<figure>

![](../../raw/assets/2025-wan/dit_block.png)

<figcaption>図10（引用）: Wan の Transformer ブロック。V-Tokens（動画トークン）が Self-Attention → Cross-Attention → FFN を通り、T-Tokens（テキスト）は Cross-Attention からのみ入る。Timestep は MLP を経て変調パラメータとして注入される。</figcaption>
</figure>

[[diffusion-model-architecture]] で追ってきた DiT 系譜の中で、Wan は**あえて古い方の分岐**を選ぶ。テキスト条件を**cross-attention** で入れるのであって、SD3 以降の主流である MM-DiT（テキストと画像を連結して完全注意で混ぜる）ではない。理由は「長い文脈のモデリング下でも指示追従を確保できるから」——動画では視覚トークンが数十万に達するので、そこにテキスト 512 トークンを連結して完全注意に混ぜると**テキストが視覚に飲み込まれる**、という判断だと読める。動画という条件下では MM-DiT が自明な最適解ではないことを示す事例である。

時空間の依存関係は **full spatio-temporal attention**（全フレーム・全空間位置が互いを見る自己注意）で捉える。関連研究で触れられる「1D 時間注意 ＋ 2D 空間注意」に分解する軽量化を採らず、正面から二次コストを払う設計である。

**adaLN の共有**が本論文で最も再利用価値の高い知見だろう。DiT の adaLN（条件からスケールとシフトを作って正規化に流す条件付け）は、ブロックごとに MLP を持つとパラメータを食う。Wan は **MLP を全ブロックで共有し、ブロックごとに異なるバイアスだけを学習する**（PixArt の AdaLN-single 系）。同一パラメータ数での比較が明快である：

| 構成 | パラメータ | 学習損失 |
| --- | --- | --- |
| Full-shared-adaLN | 1.3B | やや高い |
| Half-shared-adaLN | 1.5B | 中間 |
| **Full-shared-adaLN（35 層に深化）** | **1.5B** | **最低** |
| Non-shared-adaLN | 1.7B | Full-shared-1.5B に劣る |

結論は「**adaLN にパラメータを割くより、層を深くする方が良い**」。1.7B が 1.5B に負けるのだから、単なるパラメータ効率の話ではなく**配分の問題**だと分かる。25% のパラメータ削減。

### 3. テキストエンコーダ論争への実験的回答

直前に取り込んだ HiDream-I1（[[summaries/2025-hidream-i1]]）が 4 系統の**足し算**、Qwen-Image（[[summaries/2025-qwen-image]]）が凍結 MLLM 1 本の**引き算**という正反対の答えを出していた論点について、Wan は**アブレーションで直接比較**している。候補は umT5（5.3B, encoder-only）・Qwen2.5-7B-Instruct・GLM-4-9B。

結論は **umT5 が勝つ**。理由として引かれるのは HunyuanVideo の観察である——**decoder-only の LLM は因果注意（各トークンは前だけを見る）だが、umT5 は双方向注意なので拡散モデルに適する**。拡散モデルの条件付けは「プロンプト全体を一度に見て意味を固める」作業なので、後ろを見られない表現は不利だ、という理屈になる。HunyuanVideo に倣って双方向の token refiner をアダプタとして足しても umT5 が勝った、とも報告される。さらに Qwen-VL-7B（MLLM）と比べると FID はほぼ互角（42.91 対 43.01）だが**モデルが大きい**ため、コスト対効果で umT5 を採る。

「LLM の方が新しくて強いのだから条件エンコーダも LLM にすべき」という直観に対する、**測って否定した数少ない事例**である。

### 4. 学習インフラ — 1 サンプルが GPU に載らないとき

[[large-scale-training-infrastructure]] にまとめた通り、Wan の §4.3–4.4 は本 wiki の完全な空白地帯を埋める。要点だけ挙げる。

- **2D Context Parallel**：系列長方向に分割する並列化。外側に **Ring Attention**（マシン間、通信を計算で隠す）、内側に **Ulysses**（マシン内、高速だが全対全通信が要る）を置く。256K 系列・16 GPU で通信オーバーヘッドが **10% 超 → 1% 未満**。テンソル並列より通信が軽いのでこちらを採る。
- **活性化オフロード優先**：計算が系列長の二乗で増える一方メモリは線形なので、**長い系列ほど「計算しながら PCIe で退避する」が間に合う**。勾配チェックポインティング（再計算）は補助に回す。計算とメモリのスケーリング指数が違うことが戦略を決めている、という論理が明快である。
- **モジュールごとに分散戦略を切り替える**：VAE とテキストエンコーダは DP、DiT は DP＋CP。CP グループ内のデバイスが最初は別々のデータを読み、CP の直前にブロードキャストで揃えることで、VAE/エンコーダの時間比率を $1/CP$ に圧縮する。

### 5. Diffusion Cache — 第 3 の高速化軸

本 wiki は高速化を 2 系統で整理してきた——[[diffusion-sampling]]（学習済みモデルの**たどり方**を変える）と [[diffusion-distillation]]（**モデルそのもの**を作り替える）。Wan が持ち込むのは**どちらでもない第 3 の軸**である：モデルもサンプラーも変えず、**ステップ間で計算結果を使い回す**（[[inference-caching]]）。

2 つの観察に基づく。

- **注意の類似性**：同じ DiT ブロック内で、隣接するサンプリングステップの注意出力がよく似ている。→ 数ステップに 1 回だけ実際に計算し、他はキャッシュを再利用。
- **CFG の類似性**：サンプリングの**後期**では、条件付きと無条件の出力が似てくる。→ 無条件側を数ステップに 1 回だけ計算する。

後者は [[classifier-free-guidance]] にとって重要で、CFG が推論コストを 2 倍にするという構造的な代償を「**後期は 2 回計算する意味が薄い**」という観察で削っている。細部の劣化を防ぐため FasterCache 流の残差補償を併用する。合わせて **1.62×**。さらに FP8 GEMM（1.13×）と 8-bit FlashAttention（1.27×）を積む。

### 6. Streamer — 無限長ストリーミング生成

固定長クリップしか作れない DiT を、**ノイズ除去の待ち行列**へ作り替える。窓の中に動画トークンを並べ、**各トークンが異なるノイズレベルにある**状態で同時に処理する。一定回数のノイズ除去のあと、最左（最もクリーン）を出力して待ち行列から抜き、最右に純ノイズの新トークンを足す——これを繰り返すことで**長さの制約が消える**。

通常の拡散が「全トークンを同じノイズレベルで一斉に進める」のに対し、これは「**トークンごとにノイズレベルをずらす**」発想であり、時間軸を持つデータだからこそ成立する。連続性のため、キャッシュ済みトークンは**ノイズレベル 0 で待ち行列に再投入**され、次の窓のノイズ除去に参加する。学習時は $2w$ トークンをサンプリングして前半 $w$ を暖機に使い、損失は後半 $w$ だけで取る。

これに **LCM / VideoLCM の一貫性蒸留**（[[diffusion-distillation]]）を重ねて 4 ステップ化し、10–20 倍加速。**8 台の A100 で 15 分の動画を 8 FPS**、int8＋TensorRT 量子化で**単一 RTX 4090 で 20 FPS**。

### 7. 下流応用 7 種

- **I2V**：条件画像をゼロ埋めフレームと時間方向に連結して VAE で符号化し、**二値マスク**（1=保持、0=生成）と一緒にノイズ潜在へチャネル方向連結。入力チャネルが増えるので追加の射影層を**ゼロ初期化**で足す（ControlNet の zero convolution と同じ発想・[[controllable-generation]]）。このマスク機構は**動画継続・first-last frame 変換・フレーム補間まで同じ枠組みで扱える**——「どこを保持しどこを生成するか」を明示するだけで、タスクが切り替わる。
- **VACE（統一動画編集）**：Video Condition Unit $V=[T;F;M]$ でテキスト・フレーム系列・マスク系列を統一。**概念分離**（concept decoupling）で $F_c = F\times M$（変えるべき画素）と $F_k = F\times(1-M)$（保つべき画素）に**明示的に分けて**別々にトークン化する。学習は完全微調整と、基盤重みを触らない Context Adapter Tuning の 2 モード。
- **動画 personalization**：特筆すべき設計判断として、**ArcFace も CLIP も使わない**。ID 抽出器は顔認識の特徴に偏って傷跡やステッカーを落とし、汎用抽出器は粗すぎる——どちらも情報を失う。そこで**顔画像を Wan-VAE の潜在空間に入れて直接条件付けする**。動画の先頭に $K$ フレーム分の顔画像を継ぎ足し、**inpainting として解く**（先頭 $K$ フレームを再構成し、以降を新規生成する）。ベースモデルには一切手を入れない。
- **カメラ制御**：外部・内部パラメータを **Plücker 座標**（各ピクセルを通る光線を 6 次元で表す幾何表現）へ変換し、畳み込みで多段階特徴にして、**ゼロ初期化畳み込み**からスケール $\gamma_i$・シフト $\beta_i$ を作って各 DiT ブロックに適用する。
- **T2I**：動画の 10 倍の画像データで共同学習しているので、画像生成も強い。
- **V2A（音声生成）**：メルスペクトログラムを画像 VAE で潜在化する定石を**やめる**。パッチ化と形状変更が**時間的整合を壊す**からで、代わりに生波形上で動く **1D-VAE** を学習して $T^a \times C^a$ の潜在を得る。44.1 kHz ステレオ・最大 12 秒。

## 実験結果と知見

- **VBench**（表4）: Wan 14B が総合 **86.22%**（品質 86.67% / 意味 84.44%）で首位。**Sora の 84.28%**、HunyuanVideo の 83.24% を上回る。**Wan 1.3B ですら 83.96%** で、Kling 1.0（81.85%）や CogVideoX1.5-5B（82.17%）を超える。
- **Wan-Bench**（表2）: 自作の 14 指標。重み付きスコアで Wan 14B が 0.724、Sora 0.700、CNTopA 0.693。ただし**個別指標では負けが目立つ**——大きな動きの生成は Sora（0.482）に対し 0.415、様式化能力は CNTopB（0.623）に対し **0.328 で最下位**、人間のアーティファクトも 0.691 で最下位級。**総合首位は重み付けによって作られている**。
- **VAE**（図7）: PSNR と速度の両方で競争力。HunyuanVideo の VAE より 2.5 倍速い。
- **VAE-D のアブレーション**（表5）: 再構成損失を拡散損失に置き換えた変種は FID が一貫して悪化（15k ステップで 41.16 対 40.55）。
- **動画 personalization**（表8）: ArcFace 類似度 0.5526 は CN-TopA の 0.5655 に**負けている**。著者らも「競争力のある」としか書かない。
- **効率**: 1.3B が 8.19 GB VRAM。一方 14B は**単一ハイエンド GPU で 1 本 30 分**（最適化なし）。

## 限界・批判的視点

- **Wan-Bench が自作であり、重み付けも自作である**。総合首位は「5,000 件のペアワイズ比較から導いたピアソン相関を重みにする」手続きで得られている。個別指標では Sora や CN-TopA に負けている項目が複数あるので、**重みの決め方が結論を左右する**。FVD/FID が人間知覚と乖離するという出発点の問題意識は正当だが、代わりに置いた自動評価もまた設計者の選択を含む。[[text-to-image-generation]] の bakeyness 批判（[[summaries/2025-flux-kontext]]）と同じ論点の、動画版である。
- **競合が匿名化されている**（CN-TopA/B/C/D）。中国の商用モデルとの比較が匿名なので、再現も追試もできない。
- **様式化能力 0.328 は自ら報告した最下位**だが、本文で一切説明されない。「多様な芸術様式を巧みに扱う」という定性的主張（§4.7.1）と正面から矛盾する。
- **VAE のアブレーションが弱い**。RMSNorm 置換・特徴キャッシュ・最初のフレームの特別扱いといった設計判断について、外したときの比較がない。VAE-D の比較 1 件のみである。
- **Streamer と real-time の評価が定性のみ**。無限長生成と 8–20 FPS は魅力的な主張だが、**長時間生成での品質劣化を測る指標が提示されない**。滑動窓の外の情報が完全に失われる設計なので、数分規模で被写体やシーンの一貫性がどう崩れるかは本質的な問いのはずである（[[character-consistency]] の論点の動画版）。
- **音声生成も定性評価のみ**。MMAudio との比較は図 33 の目視で、FAD 等の標準指標がない。
- **計算コストの非対称な報告**。1.3B の 8.19 GB は強調されるが、14B の学習に要した GPU 時間・総コストは書かれていない。「$\mathcal{O}(1)$ 兆トークン」という表記も桁だけである（レポート全体でデータ量が $\mathcal{O}(\cdot)$ 記法で伏せられる）。
- **図が 4 枚欠落している**（図 4・11・13・14）。ar5iv・arXiv HTML のどちらでも画像が生成されておらず、Wan-Bench の次元構成（図 13）と DiT 並列化の図解（図 11）は本文の記述からしか追えない。
- **著者らが挙げる限界**：大きな動きの場面で細部が保てない、14B の推論が単一 GPU で 30 分、教育・医療といった専門領域が弱い。

## 用語と略称

- **T2V / I2V / V2V / V2A** = Text-to-Video / Image-to-Video / Video-to-Video / Video-to-Audio。
- **DiT** = Diffusion Transformer。**MM-DiT** = Multimodal DiT（テキストと画像を連結して完全注意で扱う SD3 の設計。Wan は採らない）。
- **VAE** = Variational Autoencoder。**3D causal VAE**：時間軸を持ち、未来が過去に影響しないことを保証する動画用 VAE。
- **causal convolution（因果畳み込み）**：出力が現在と過去の入力のみに依存する畳み込み。
- **GroupNorm / RMSNorm**：前者はチャネル群で統計量を取る正規化（フレーム間で情報が漏れる）、後者は二乗平均平方根のみで正規化する軽量な変種（漏れない）。
- **adaLN** = adaptive Layer Normalization。条件からスケールとシフトを作る条件付け。**AdaLN-single**：その MLP を全ブロックで共有する PixArt 由来の省パラメータ版。
- **umT5**：多言語 T5 の一種。encoder-only で**双方向注意**を持つ。
- **flow matching / rectified flow**：ノイズとデータを線形補間し、その速度 $v_t = x_1 - x_0$ を予測する定式化。
- **logit-normal サンプリング**：タイムステップ $t$ を logit-normal 分布から引き、中間ステップに学習を集中させる（SD3 由来）。
- **CFG** = Classifier-Free Guidance。条件付きと無条件の予測を組み合わせて条件忠実度を上げる手法。推論コストが 2 倍になる。
- **FSDP** = Fully Sharded Data Parallel。**DP / TP / SP / CP** = Data / Tensor / Sequence / Context Parallelism。
- **Ring Attention / Ulysses**：系列長方向に注意計算を分割する 2 つの方式。前者はブロックを環状に回し、後者は全対全通信でヘッドを配り直す。
- **GC** = Gradient Checkpointing（活性化を捨てて逆伝播時に再計算する）。**活性化オフロード**：活性化を CPU メモリへ退避する。
- **GEMM** = General Matrix Multiply。**MFU** = Model FLOPs Utilization（理論ピーク性能に対する実効利用率）。
- **LCM** = Latent Consistency Model。**VideoLCM**：その動画版。数ステップ生成のための一貫性蒸留。
- **Plücker 座標**：3 次元空間の直線を 6 次元ベクトルで表す幾何表現。ピクセルごとの光線を符号化するのに使う。
- **PSNR** = Peak Signal-to-Noise Ratio（再構成の画素レベルの忠実度）。**FVD** = Fréchet Video Distance。**FID** = Fréchet Inception Distance。
- **VBench**：動画生成を 16 次元で評価する公開ベンチマーク。**Wan-Bench**：本論文が提案する 14 指標・3 次元の自作ベンチマーク。
- **RAFT**：オプティカルフロー推定モデル。**MANIQA / MUSIQ**：画質評価モデル。**SAM2 / Grounding DINO / RAM**：セグメンテーション・検出・タグ付けのモデル。
- **VCU** = Video Condition Unit（VACE がテキスト・フレーム・マスクを統一する入力形式）。
- **ArcFace / InstantID**：顔認識の埋め込みモデル／顔の同一性を保つ画像生成手法。

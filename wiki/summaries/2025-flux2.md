# FLUX.2：コードから読むアーキテクチャ

> 原典: `code_analysis/flux2/`（コミット `50fe516`）・[github.com/black-forest-labs/flux2](https://github.com/black-forest-labs/flux2)
> 開発: Black Forest Labs ・ FLUX.2 [dev] 2025-11-25 / FLUX.2 [klein] 2026-01-15

> ⚠️ **本ページはコードを一次資料とする。** FLUX.2 には技術報告書が存在せず、README とモデルカードも **32B（dev）以外のパラメータ数・ブロック数を一切書かない**。以下の構成値はすべて実装から読み取り、ファイル名と行番号を添えてある。**学習の詳細・データ・蒸留手法は本リポジトリからは分からない**（推論専用のコードである）。

## 一言まとめ

FLUX.1 の二重ストリーム＋単一ストリームという二相構成を保ちつつ、**条件付けの機構をほぼすべて作り替えた**モデル群。pooled CLIP ベクトルを廃し、テキストエンコーダを LLM の**中間 3 層の連結**に置き換え、**変調（modulation）をブロックごとではなくモデル全体で 1 回**に共有し、VAE の `scale_factor`/`shift_factor` を**学習済み BatchNorm** に置換した。4 軸 RoPE の第 1 軸で参照画像を分離し、klein-9B-kv では参照トークンの K/V を**近似ではなく厳密に**キャッシュする。

## 3 変種の構成（`src/flux2/model.py` L11–49）

レジストリには 6 エントリあるが、**アーキテクチャは 3 種類**しかない（`src/flux2/util.py` L15–88）。

## 入力・処理・出力

```
テキスト ──▶ [LLM]（中間 3 層を連結）──▶ txt_in: Linear(context_in_dim → hidden)
                                                    │
画像 ──▶ [VAE encode]（f8 conv ＋ 2×2 pixel-shuffle）│
          → (128, H/16, W/16) → flatten → img_in: Linear(128 → hidden)
                                                    │
timestep ──▶ timestep_embedding(256) ──▶ time_in ──▶ vec
             (+ guidance_in、dev のみ)               │
                                                    ▼
                        ┌───────────────────────────────────────┐
                        │ DoubleStreamBlock ×depth              │  txt と img は別重み
                        │   （attention のときだけ q,k,v を連結）│
                        ├───────────────────────────────────────┤
                        │  cat((txt, img), dim=1)  ← ここで合流  │
                        ├───────────────────────────────────────┤
                        │ SingleStreamBlock ×depth_single_blocks │  共有重み
                        └───────────────────────────────────────┘
                                    │
                        img[:, num_txt_tokens:]  ← テキストを剥がす
                                    │
                        final_layer（LastLayer）
                                    ▼
                            速度場（velocity）
```

`forward()` の実引数は `(x, x_ids, timesteps, ctx, ctx_ids, guidance)`（L115–120）。`x` は `(B, L_img, 128)`、`ctx` は `(B, L_txt, context_in_dim)`、戻り値は `(B, L_img, 128)`。

## 条件付けの 3 経路

### (1) テキスト — cross-attention は存在しない

二重ストリームブロックでは txt と img が**別の重み**（`img_attn.qkv` / `txt_attn.qkv` など）を持つが、attention の直前で `q = torch.cat((txt_q, img_q), dim=2)` と連結され（L594）、**joint attention** になる。L153 で `img = torch.cat((txt, img), dim=1)` と系列そのものが合流し、以降の単一ストリームブロックは**共有重み**で処理する。最後に `img[:, num_txt_tokens:]` でテキストを剥がす。

[[concepts/diffusion-model-architecture]] の系譜でいう **MM-DiT（二重）→ 単一ストリーム**の二相構成で、FLUX.1 と同じ。Z-Image（[[summaries/2025-z-image]]）が入口の 2 ブロックを除き完全に単一ストリームなのとは対照的である。

### (2) タイムステップ — 変調が**全ブロックで共有される**

**これが FLUX.1 からの最も大きな設計変更**である。変調ベクトルはモデルの最上位で**1 回だけ**作られ（L98–108）、同じタプルが**全ブロックに渡される**。

```python
self.double_stream_modulation_img = Modulation(hidden_size, double=True, disable_bias=True)
self.double_stream_modulation_txt = Modulation(hidden_size, double=True, disable_bias=True)
self.single_stream_modulation      = Modulation(hidden_size, double=False, disable_bias=True)
```

**FLUX.1 にあったブロックごとの `img_mod.lin` / `txt_mod.lin` / `modulation.lin` は存在しない。** DiT 全体で変調に使われる重みは、上記 3 つの `.lin` と `final_layer.adaLN_modulation.1` の**計 4 行列だけ**である。

これは本 wiki が別々に記録してきた 2 つの知見の 3 例目にあたる——Wan は adaLN の MLP を全層で共有し（[[summaries/2025-wan]]）、Z-Image は変調射影の下方射影を全層共有にした（[[summaries/2025-z-image]]）。**「条件付け機構は思ったより安く済ませてよい」という判断が、独立した 3 チームから重ねて出ている。**

### (3) guidance — 蒸留と真の CFG が同居する

- **dev のみ `use_guidance_embed=True`**。guidance スカラーを `timestep_embedding(guidance, 256)` で埋め込み、`vec` に**加算**する（L126–130）。1 回の順伝播で済む。
- **klein の蒸留版は `use_guidance_embed=False`**。`denoise` は `guidance_vec` を作って渡すが、**`forward` はそれを完全に無視する**。guidance の摘みが存在しない。
- **klein-base のみ真の CFG**。`denoise_cfg`（`sampling.py` L364–410）がバッチを 2 倍に複製して 1 回の順伝播で cond と uncond を同時に走らせ、`pred_uncond + guidance * (pred_cond - pred_uncond)` を取る。

**pooled CLIP ベクトルは廃止された。** FLUX.1 にあった `vec_in_dim` / `y` は FLUX.2 には存在せず、`vec` は時刻（＋ dev では guidance）だけから作られる。テキストは `txt_in` の 1 本のみで入る。

## 4 軸 RoPE `(t, h, w, l)`

`axes_dim = [32,32,32,32]`、`theta = 2000`（10000 ではない）。位置 id は `torch.cartesian_prod` で構成される（`sampling.py` L93–151）。

| トークン | t | h | w | l |
| --- | --- | --- | --- | --- |
| テキスト | 0 | 0 | 0 | **トークン索引** |
| 対象画像 | 0 | 0..H/16 | 0..W/16 | 0 |
| **参照画像 $i$** | **10·(i+1)** | 0.. | 0.. | 0 |

参照画像は `scale = 10` の刻みで**第 1 軸だけをずらす**（L74–80）。空間座標は対象画像と重なったままで、分離は RoPE の位相だけが担う。

```python
t_off = [scale + scale * t for t in torch.arange(0, len(encoded_refs))]
```

これは FLUX.1 Kontext の**仮想タイムステップ**（[[summaries/2025-flux-kontext]]）そのもので、[[concepts/position-embedding]] に記録した設計がコードで確認できた形である。Z-Image の 3D Unified RoPE も同型の解に独立に到達している。

## VAE — `scale_factor` / `shift_factor` が消えた

`AutoEncoderParams`（`autoencoder.py` L9–17）は `ch=128`, `ch_mult=[1,2,4,4]`, `z_channels=32`, `resolution=256`。**`scale_factor` も `shift_factor` も存在しない。** 代わりに `affine=False` の学習済み **`BatchNorm2d`** が正規化統計として使われる（L293–312）。

```python
self.ps = [2, 2]
self.bn = torch.nn.BatchNorm2d(math.prod(self.ps) * params.z_channels,  # = 4 * 32 = 128
                               eps=1e-4, momentum=0.1, affine=False, track_running_stats=True)
```

FLUX.1 の**大域スカラー 2 つ**（shift, scale）が、**128 チャネルそれぞれの (shift, scale)** に一般化されたことになる。

**実効圧縮率は f16**だが、その作り方が特徴的である。

1. conv スタックの `Downsample` が 3 段で **8×**（`ch_mult` が 4 要素）
2. `encode` が平均だけを取り、`"... c (i pi) (j pj) -> (c pi pj) i j"` の **2×2 pixel-shuffle** でさらに 2×

結果は **f16・潜在 128 チャネル**で、これが `in_channels = 128` と一致する。**DiT 側に patchify は存在しない**——`img_in` はただの `Linear(128, hidden)` で、**VAE の pixel-shuffle が patchify を兼ねている**。[[concepts/image-tokenizer]] の「同じ圧縮率への 2 つの到達路」（VAE で払うか patchify で払うか）に対し、FLUX.2 は**VAE の内側で両方をやる**という第 3 の答えを出している。

その他の特徴：attention は**mid-block にのみ**存在し（down/up の `attn` は空の `ModuleList` で dead path）、単一ヘッドの大域 self-attention。推論時に KL のサンプリングはせず平均を決定的に返す。

## テキストエンコーダ — 最終層を使わない

`text_encoder.py` L26–27、L247、L418。**最終層ではなく中間 3 層の隠れ状態を特徴軸で連結する。**

| エンコーダ | 抽出層 | d_model | 3×d_model | 対応する `context_in_dim` |
| --- | --- | --- | --- | --- |
| Mistral-Small-3.2-24B（dev） | **[10, 20, 30]** | 5120 | **15360** | `Flux2Params` ✅ |
| Qwen3-8B-FP8（klein 9B） | **[9, 18, 27]** | 4096 | **12288** | `Klein9BParams` ✅ |
| Qwen3-4B-FP8（klein 4B） | **[9, 18, 27]** | 2560 | **7680** | `Klein4BParams` ✅ |

```python
out = torch.stack([output.hidden_states[k] for k in OUTPUT_LAYERS_QWEN3], dim=1)
return rearrange(out, "b c l d -> b l (c d)")
```

最深の tap でも Mistral は 40 層中 30、Qwen3 は 36 層中 27 であり、**最終層の表現は一切使われない**。LLM の最終層は次トークン予測に特化しており、中間層の方が意味を保持しているという判断である。`MAX_LENGTH = 512`。

なお **9B モデルには 8B のテキストエンコーダ**が組み合わされる（`Qwen/Qwen3-8B-FP8`）——名前の不一致は意図的である。

## 推論：ノイズ除去

### 時刻の向き（⚠️ Z-Image と逆）

**t=1 が純ノイズ、t=0 がクリーン画像。** `get_schedule` は `torch.linspace(1, 0, num_steps + 1)` で**降順**に刻む（`sampling.py` L244–248）。更新式は 3 つのサンプラで共通（L305 / L353 / L408）：

```python
img = img + (t_prev - t_curr) * pred
```

`t_prev < t_curr` なので係数は**負**である。したがってモデルが予測する速度は $v_\theta \approx \epsilon - x_0$（画像からノイズへ向かう向き）で、それを負の $\Delta t$ で足すことがノイズ除去になる。SD3 / FLUX.1 と同じ規約であり、**Z-Image（$t=0$ がノイズ）とは逆向き**である（[[questions/z-image-figure10-architecture-walkthrough]]）。

積分器は**1 次の陽的オイラー法のみ**。Heun も RK も、ancestral なノイズ注入もない。

### スケジュール — μ が直接コードに現れる

```python
def generalized_time_snr_shift(t, mu, sigma):
    return math.exp(mu) / (math.exp(mu) + (1 / t - 1) ** sigma)
```

$\sigma=1$ ならこれは標準のシフト $t' = s t/(1+(s-1)t)$ と代数的に等価で、**シフト係数は $s = e^{\mu}$** である。[[concepts/noise-schedule]] に記録した FLUX.1 Kontext の導出——**$\alpha$ シフトは $\mu = \log\alpha$ の logit-normal と等価**——が、コードにそのまま $\mu$ という変数名で現れていることになる。

FLUX.1 の `base_shift` / `max_shift` の線形補間は**廃止された**。代わりに $\mu$ は `compute_empirical_mu`（L255–266）で **`(image_seq_len, num_steps)` の 2 次元経験フィット**として計算される。2 本の直線（10 ステップ用と 200 ステップ用）を系列長について引き、それをステップ数で線形補間する。

**ここに新しい軸がある——ステップ数が少ないほどシフトが大きくなる。** 1360×768（4080 トークン）で計算すると、50 ステップで $s\approx 7.6$、4 ステップで $s\approx 9.9$。少ステップでは高ノイズ域に時間予算を厚く配る、という**スケジュール側からの蒸留の補完**になっている。

### NFE

| モデル | steps | CFG | 総 NFE |
| --- | --- | --- | --- |
| `flux.2-dev` | 50 | 蒸留（埋め込み） | 50 |
| `flux.2-klein-*`（蒸留版） | **4** | 蒸留（無視） | **4** |
| `flux.2-klein-base-*` | 50 | **真の CFG（×2）** | **100** |

klein は guidance と num_steps の**両方**が `fixed_params` に入っており、CLI が他の値を拒否して `sys.exit(1)` する（`cli.py` L212–238）。`util.py` のコメントが明示する：`# guidance and timestep distilled`。**klein は guidance 蒸留かつステップ蒸留**である（[[concepts/diffusion-distillation]]）。

## KV キャッシュ（klein-9B-kv）— 近似ではなく厳密

`denoise_cached`（`sampling.py` L310–355）と `forward_kv_extract` / `forward_kv_cached`（`model.py` L170–326）。**ブロックごとに参照画像トークンの K/V だけ**をキャッシュする。

```python
cache = {"k_ref": k[:, :, ref_start:ref_end, :].clone(),
         "v_ref": v[:, :, ref_start:ref_end, :].clone()}
```

**なぜキャッシュが厳密に等価なのか**——2 つの設計がそれを保証する。

1. **参照トークンは自分自身にしか attend しない。** `causal_attn_fn`（L758–815）が実装するのはブロックマスクで、参照は txt もノイズ付き対象も見ない。つまり参照の活性化は $x_t$ に依存しない。
2. **参照トークンは固定タイムステップで変調される。** `ref_fixed_timestep: float = 0.0`（L180、L198）で `ref_vec` を別に作り、参照位置の変調パラメータだけを差し替える。参照は常に「クリーンなデータ」として扱われる。

したがって参照の K/V は軌道上で**文字どおり不変**であり、再利用は再計算と**数学的に同一**である。

**これは [[concepts/inference-caching]] に新しい系統を加える。** Wan の Diffusion Cache（[[summaries/2025-wan]]）は「隣接ステップで注意出力が似ている」という**経験的な近似**を突くもので、間隔を検証集合で選ぶ必要があり残差補償も併用する。FLUX.2 のそれは**構造で不変性を作ってから使い回す**もので、品質の劣化が原理的に起こらない。

ただし代償がある。この不変性は「参照が他を見ない」という**制約された注意**によって買われており、**非キャッシュ版とは別のチェックポイント**になる（`flux.2-klein-9b-kv`）。実行時の切り替えではない。素の `forward` は `num_ref_tokens=0` で同じブロックメソッドを呼ぶため、参照専用マスクも固定時刻変調も**効かない**。

## 画像条件付け（編集）

参照画像は `encode_image_refs`（`sampling.py` L52–90）で VAE 符号化され、**系列に連結される**。チャネル連結でもマスクでもない。

```python
img_input = torch.cat((img_input, img_cond_seq), dim=1)
```

系列の並びは経路によって違う——素の経路は **[txt, 対象, 参照]**、KV キャッシュ経路は **[txt, 参照, 対象]**。参照画像は対象と解像度が一致する必要がなく、それぞれ独立に符号化して連結される。画素予算は参照 1 枚なら 2024²、複数なら 1024²。

## LoRA を当てるなら（実装から読める標的名）

本リポジトリに**学習コードは一切ない**（オプティマイザも損失も PEFT もなく、`load_state_dict(..., strict=True)`）。README は「Base（50 ステップ）を fine-tuning と LoRA 学習に使え」と述べるのみ。以下は実装から読める標的名である。

| ブロック | 標的モジュール名 |
| --- | --- |
| `DoubleStreamBlock` | `img_attn.qkv` / `img_attn.proj` / `img_mlp.0` / `img_mlp.2` ＋ `txt_*` の対 |
| `SingleStreamBlock` | `linear1`（QKV ＋ MLP-in の融合）/ `linear2`（attn-out ＋ MLP-out の融合） |
| 変調（**全ブロック共有・計 4 つ**） | `double_stream_modulation_img.lin` / `double_stream_modulation_txt.lin` / `single_stream_modulation.lin` / `final_layer.adaLN_modulation.1` |

**重要な含意**：FLUX.1 向けの LoRA レシピにはブロックごとの `img_mod.lin` を標的にするものがあるが、**FLUX.2 にそのモジュールは存在しない**ので空振りする。逆に、共有変調の 4 行列に LoRA を当てると**全ブロックに一斉に効く**——Z-Image の共有下方射影と同じ性質で、レバーが長すぎて制御しにくい（[[questions/z-image-architecture-and-lora-placement]]）。

MLP は **GLU**である。`img_mlp.0` は `mlp_hidden*2` を出力し、`SiLUActivation`（L390）が `chunk` してゲートする。

## 独立した裏づけ — 学習ツール側の実装（2026-08-26 追記）

本ページの構成値は公式リファレンス実装 1 つだけを根拠にしていたが、**別系統の実装からの独立確認**が取れた。ostris/ai-toolkit（[[summaries/2026-ai-toolkit]]）は FLUX.2 の学習をサポートするために、**BFL の dataclass 群を自前で vendoring している**。

- `Flux2Params` / `Klein9BParams` / `Klein4BParams` の**全フィールドが本ページの表と一致する**。klein 4B が **5 double + 20 single・hidden 3072・heads 24** であることは、これで 2 つの独立した実装が支持する事実になった（Web の二次情報が誤っていた件は下記「限界」を参照）。
- テキストエンコーダの中間層指定（Mistral `[10,20,30]` / Qwen3 `[9,18,27]`）、`context_in_dim` の一致、theta=2000 の 4 軸 RoPE も同じ。

**一方で、学習側では落とされている機構がある。**

| 機構 | 推論リファレンス | ai-toolkit（学習） |
| --- | --- | --- |
| KV キャッシュ（`forward_kv_extract` / `forward_kv_cached` / `causal_attn_fn` / `_blend_*_mods`） | あり | **削除。素の full attention のみ** |
| 参照画像の固定タイムステップ変調 | あり | 対応する経路なし |
| guidance embed | dev で有効 | 保持 |

学習では毎ステップ全トークンを attend するため、**推論時の因果マスク付き参照処理と厳密には同じ計算をしていない**。参照画像を含む編集モデルの LoRA 学習では、この差が影響しうる。ただし本ページ「KV キャッシュ」節で示したとおり、キャッシュは数学的に等価な最適化なので、**full attention で学習して cached 推論に載せること自体は整合する**（逆に、cached 側の因果マスクが学習では効いていない点だけが差分になる）。

もう一点、**LoRA を当てるなら**節の補強として——ai-toolkit の FLUX.2 実装は標的ブロックを `["double_blocks", "single_blocks"]` と宣言しており、**本ページが強調した「全ブロック共有の 4 つの変調行列」は既定で学習対象から外れる**。共有変調を狙う LoRA レシピは、設定を明示的に書き換えない限り成立しない。

## 限界・批判的視点

- **技術報告書がない。** 学習データ・学習手順・蒸留の具体（何を教師にどう蒸留したか）が一切分からない。本ページが記述できるのは**推論時の構造だけ**である。Z-Image が 314K GPU 時間・$628K まで公開した（[[summaries/2025-z-image]]）のとは透明性の水準が違う。
- **公開ドキュメントが構成を書かない。** README とモデルカードは 32B（dev）以外のパラメータ数もブロック数も書かない。その結果、**外部の解説サイト（DeepWiki）が klein 4B を「8 double + 24 single」と誤って記述しており**、本 wiki も一度その誤りを取り込んだ（[[questions/lora-merging-base-model-selection]] で訂正済み）。正しくは **5 + 20** で、8 + 24 は klein 9B の値である。**一次資料がコードしかないモデルでは、二次情報を信用してはいけない。**
- **レジストリに不整合がある。** `flux.2-dev` は `"guidance_distilled": True` なのに `fixed_params` が `{}` で、guidance も steps も自由に変えられる（`util.py` L77–87）。フラグの意味が変種によって揺れている。
- **デバッグ分岐が共有状態を壊す。** `load_flow_model`（L95–96）はデバッグ時に `config["params"].depth = 1` と**共有 dataclass インスタンスを破壊的に書き換える**。同じレジストリエントリを再利用すると副作用が残る。
- **README のライセンス表記が割れている。** 表は `LICENSE-FLUX-NON-COMMERICAL`（typo を含む）を指し、本文の別箇所は `LICENSE-FLUX-DEV` を指す。
- **KV キャッシュ版は別チェックポイント**であり、素のモデルと数値的に同一ではない。「キャッシュを有効にする」という実行時オプションではない点は、ドキュメントからは読み取りにくい。
- klein のローカル・プロンプト upsampling は**未実装**（`Qwen3Embedder` が `NotImplementedError` を投げる）。安全性フィルタも Mistral 側にしかない。

## 用語と略称

- **DiT** = Diffusion Transformer（[[concepts/diffusion-model-architecture]]）。
- **DoubleStreamBlock / SingleStreamBlock** = テキストと画像に別重みを与えるブロック / 連結系列を共有重みで処理するブロック。
- **modulation（変調）** = 条件ベクトルから (shift, scale, gate) を作り、正規化後の活性化を変調する adaLN 系の機構。
- **GLU** = Gated Linear Unit。出力の半分をゲートとして掛ける FFN 構成。
- **RoPE** = Rotary Position Embedding。ここでは 4 軸 `(t,h,w,l)`、`theta = 2000`。
- **NFE** = Number of Function Evaluations、モデル評価回数。CFG を使うと 1 ステップで 2 回になる。
- **f16** = 空間解像度を 16 分の 1 に圧縮すること（[[concepts/image-tokenizer]]）。
- **pixel-shuffle（space-to-depth）** = 空間次元をチャネル次元へ畳む操作。ここでは 2×2 でチャネルが 4 倍になる。
- **rectified flow** = ノイズとデータを直線で結び、その速度場を回帰する定式化（[[concepts/flow-matching]]）。
